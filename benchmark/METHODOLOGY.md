# Methodology and interpretation

The source corpus contains 16 full primary filings/releases/transcripts with pinned URLs, fiscal periods and raw hashes. The 50-case suite contains factual answer points, citation requirements, short source locators and separate behavioral rubrics. Targets see company scope and question text only. Evaluator-selected evidence and expected document lists do not guide retrieval.

Uploaded documents are titled with their canonical corpus IDs (for example `nvda_2025_10k`), as in the September captures. Every question sees the same corpus metadata; this is not a per-case expected-document selection. Because an explicit citation document ID is authoritative, a title or label naming the right document cannot make a wrong or unmapped citation score.

Copilot uses its existing deterministic local provider against a fresh unseeded corpus. HTML/PDF ingestion follows production extraction, without the SEC downloader's truncation path. The baseline consumes exactly the same complete production-extracted text. Pinned normalized text is used only to verify source/evidence provenance; it is not substituted for production upload text. API settings are 128 embedding dimensions, an 800-token chunk target, 80-token overlap, minimum retrieval score 0.04 and a 10 MB upload limit.

## Baseline

Split each document into non-overlapping 1,200-character chunks. Count distinct lowercase alphanumeric question-token overlap after removing the fixed stopword list in [run.py](run.py). Restrict to requested company tickers. Select up to three positive-overlap chunks, breaking ties by canonical document ID then character offset. Concatenate the first 400 characters of each selected chunk and cite it. Refuse only when every overlap is zero. This baseline has no synthesis, model, period filter or financial refusal policy. Its fixed configuration is recorded in every run.

## Scorer v3

The scorer retains lexical answer-point coverage and citation-metadata checks. Quantity normalization equates supported USD symbol/word forms, thousands separators and million/billion scales, while keeping percentages distinct. Local quantity checks flag opposite/negated direction and simple negative amount assertions ("was not $X", "did not equal $X"). An answer quantity is compared with an equal-valued point quantity only when its clause shares a metric word or a topic word with the point (so "Data Center business fell 142%" contradicts "Data Center sales rose 142%"). Different metric words, disjoint topic words, or a new named subject inferred from capitalization inside the sentence block this binding. For example, "NVIDIA Gaming sales declined 10%" does not contradict "NVIDIA Data Center sales rose 10%" despite the shared company name and metric. Sentence-initial capitals and short all-caps tickers/acronyms are excluded from the new-name heuristic. Lowercase names, unexpected capitalization, aliases and pronoun-only clauses can still cause misses or false flags; clauses without a shared anchor, such as "it fell 142%", are not checked. These lexical anchors do not resolve every entity, period or clause attachment; numeric occurrence elsewhere can still satisfy an answer point, and arbitrary contradictions are not all recognized.

Finite phrase rules flag affirmative advice, numeric price targets, return guarantees, certainty language and numeric forecasts appended to an expected refusal. A price target is flagged when a non-year amount ("$200", "200 dollars", "USD 200" or "200") follows the phrase within four words; years ("a price target for fiscal 2026") are not values, and a value denied before or immediately after ("is not $200", "of $200 is not supported") is not asserted. Quoted spans, questions and locally negated mentions are excluded by heuristics. Such exclusions and finite patterns can miss unsupported claims or flag legitimate sourced language. The `severe_hallucination` compatibility field therefore denotes **deterministic severe flags**, not an independently verified hallucination rate. Inspect per-case `unsupported_assertions` and `contradicted_points` diagnostics.

An explicit citation document ID is authoritative. A verified upload map canonicalizes UUIDs for scoring; a wrong/missing/unmapped ID cannot be rescued by prose. Citation metadata checks establish identity/format coverage, not whether the quoted evidence supports the answer or was faithfully retrieved. The caller's mapping is not cryptographic proof of attribution. Original raw UUID responses and the mapping hash remain available for local audit.

Manual `judge_rubric` and semantic review are **not performed** by the deterministic scorer. A passed gate covers only the declared deterministic checks. Human evidence/meaning review remains necessary, including when a score passes. Quality fixture replay exercises scorer/report plumbing and is not an independent model evaluation.

Errors/empty responses fail cases, but refusal behavior is evaluated only for nonempty, error-free responses. Refusal accuracy uses that behavioral denominator, with evaluated/unavailable counts exposed; it is zero if nothing is evaluable. Other aggregate quality scores and error rate retain all attempted cases.

## Provenance and comparisons

Each new capture records suite/evidence/runner hashes, checkout commit and cleanliness, interpreter version, source hashes, extraction hashes, map hash, configuration and per-response timestamps/hashes. A dirty checkout is disclosed; its commit hash alone does not identify local modifications. For a shareable run, use clean, committed checkouts and retain their revisions. API settings are supplied by the documented server/ingestion workflow and recorded; the response provider contract and corpus counts are checked, without treating an arbitrary remote server as authenticated.

This directory is the current scorer-v3 workflow. It does not recreate September 18's historical 34/50 result: that figure belongs to its original scorer-v2 suite/target/capture configuration. A new run against the same source corpus can have different scores and must be labeled as a new baseline. This public method/code does not expose the historical full response text or claim independent rescoring of it. Older harness checkouts lack `benchmark/`; keep the current checkout for these commands rather than checking out an older harness and attempting to run missing scripts.

Changing scorer semantics, cases, evidence or sources requires a new baseline. `compare --gate` rejects different scorer versions, changed fingerprints and mismatched case sets. Existing historical reports/captures remain historical; do not overwrite or silently regrade them. Offline rescoring is a new derivative with its own scorer/rescoring timestamp, not fresh execution.

## Timing and cost

Use `perf_counter` around each answer call. API latency includes loopback HTTP and conversation persistence; baseline latency is in-process. Source fetch, extraction, ingestion and baseline indexing are excluded. Calls are sequential in suite order, API then baseline, without warmup or retries. Integer milliseconds round sub-millisecond durations down: a 0 ms measurement is not zero execution time. These differing service boundaries do not establish an apples-to-apples service speedup or model inference benchmark. Both targets use no LLM and report zero model API cost.

## Public export boundaries

Full filings, derived text and raw target prose stay local. The public exporter verifies the fixed workflow artifact inventory and validates all retained non-gold input records before writing export files. Configuration, result metadata, source provenance, captures, scored-result values, gates and ingestion have typed/value checks: counts, dates, versions, hashes, reviewed constants, settings and identities cannot be replaced by arbitrary prose. Cross-file checks link maps, source/upload identities and hashes, corpus counts, requests, response fingerprints, call timings and case definitions. Summary/category metrics and gates are checked against the saved case metrics; answer text is never rescored or regraded. Invalid inputs abort the export, with no final output directory. Unknown inventory filenames and unclassified retained fields stop the export; keep free-form review notes outside the measured capture directory.

Source URLs must be credential-free HTTPS URLs with named hosts and no port, query or fragment. Hosts must use valid ASCII DNS labels with a letter-led final label; terminal root dots, IP literals, legacy numeric IPv4 spellings and local host suffixes are rejected. This policy accepts all 16 pinned source URLs. Source and upload URLs must agree when both are recorded. It is a syntax/consistency policy, not DNS authentication or a general detector of secrets encoded into a URL path or an identifier. Local path fields and the API data directory are dropped. Invalid target numeric metadata is redacted, unknown model labels are redacted, and target free text is omitted or fingerprinted. The final path scan is a secondary check over the staged output.

The exporter retains the suite's curated facts/rubrics/short locators, identifiers and provenance. Curated `case_definition` values are the explicit gold trust boundary; copied gold fields and both targets' definitions must match it. The exporter does not establish those facts' correctness or sanitize deliberately inserted private text in that trusted gold. Some hashes refer to original local files not published here (for example the full local ingestion manifest); their syntax is validated but their original bytes cannot be recovered or authenticated from the redacted export. Caller-supplied identifiers and internally consistent records are not cryptographic proof of truthful attribution. Inspect evaluator content before publication.

Public response hashes fingerprint original prose without revealing it. Public records support inspection of requests, identifiers, metrics, denominators and provenance but cannot independently recompute lexical scores from missing answers. Reproduce from the public sources into new local directories to obtain fresh full responses. Changed source bytes, access restrictions and unavailable URLs can prevent exact reproduction; source drift is an explicit failed check, never a replacement by reference answers.
